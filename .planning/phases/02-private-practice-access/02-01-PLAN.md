## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Test process → ephemeral HTTP server | Tests send requests through a real local socket and must not expose captured credentials or email links. |
| Test process → temporary SQLite files | Each test fixture owns its database file and tears it down after use. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Information disclosure | Captured verification/reset messages | medium | mitigate | Keep messages in per-fixture memory, expose links only to the owning test, and never log bodies or tokens. |
| T-02-02 | Tampering | Test database fixture | low | mitigate | Use a unique database per fixture and close/remove it during `finally` teardown. |
| T-02-SC | Tampering | Future npm package installation | high | mitigate | Plan 02-02 requires official Better Auth provenance and tarball verification before Plan 02-03 installs any new package. |

Residual threats: local test data is visible to the developer running the test process; no production account data or secrets are used by this harness.
</threat_model>
