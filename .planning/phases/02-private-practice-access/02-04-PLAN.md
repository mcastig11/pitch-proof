## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser to auth HTTP | Untrusted credentials, reset tokens, Origin, cookies, and retry patterns cross into the server. |
| Auth handlers to SQLite | Account, verification, password, reset-token, and session state is persisted and must change atomically. |
| Server to email transport | Verification and reset links are secret-bearing messages sent through injected transport. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-03 | Spoofing | Password reset and verification endpoints | high | mitigate | One-use expiring tokens, verified-email gate, generic public responses, and all-session revocation after password update. |
| T-02-04 | Elevation of privilege | Session issuance and private-request guard | high | mitigate | Fixed seven-day server expiry, disabled refresh/cache, session rotation, and database-backed per-request authorization tests. |
| T-02-05 | Information disclosure | Signup, resend, reset, and private responses | high | mitigate | Uniform response semantics, no-store headers, per-IP/account throttles, and response-parity tests. |
| T-02-SC | Tampering | npm package installation | high | mitigate | Preserve the blocking Better Auth provenance/tarball checkpoint from plan 02-02 before package installation in plan 02-03. |

Residual threats: a process-local rate limiter can be bypassed across multiple server replicas; any multi-replica deployment must use a shared limiter before exposure. Email delivery may be delayed or rejected upstream, so the pending screen preserves safe resend and retry behavior.
</threat_model>
