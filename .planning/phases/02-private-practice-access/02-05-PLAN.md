## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Application server to Resend | Server sends token-bearing verification/reset emails using a secret API credential. |
| Runtime configuration to server | Environment values configure external transport and must not flow to browser assets or logs. |
| Auth callback to transport | Secret links cross an internal adapter boundary and must only be delivered to the intended recipient. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-06 | Information disclosure | Resend API key and reset/verification messages | high | mitigate | Keep key server-side, use HTTPS and Bearer header, inject transport, sanitize logs, and test that token URLs are absent from errors. |
| T-02-07 | Denial of service | Resend HTTP adapter | medium | mitigate | Bound request timeout, check status, surface retryable generic failure, and rate-limit upstream auth operations in plan 02-04. |
| T-02-SC | Tampering | npm package installation | high | mitigate | No Resend package is installed; preserve the blocking Better Auth provenance/tarball checkpoint before the existing package installation plan. |

Residual threats: Resend may delay, bounce, or reject email after accepting a request; the app cannot guarantee inbox delivery. Users can request a fresh message, and operators must monitor provider delivery outside this application.
</threat_model>
