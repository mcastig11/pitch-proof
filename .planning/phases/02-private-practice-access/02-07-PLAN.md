## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser to private-resource HTTP | Resource IDs and forged owner claims are attacker-controlled; only validated server session state is trusted. |
| Express route to SQLite | A missing owner predicate could cross account boundaries. |
| Express route to byte provider | Byte delivery must occur only after a fresh owner check and must not expose raw storage paths. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-02 | Information disclosure | Resource metadata and byte endpoints | critical | mitigate | Derive owner only from session.user.id on every read, perform owner-scoped lookups, hide foreign resources as 404, and test two-account direct requests. |
| T-02-11 | Elevation of privilege | Owner identity inputs | high | mitigate | Ignore/reject caller-provided owner IDs and verify forged URL/body/header values cannot change session-derived identity. |
| T-02-12 | Information disclosure | Byte provider and caching | high | mitigate | Authorize metadata before provider call, expose no filesystem paths, and set no-store for every private response. |
| T-02-SC | Tampering | npm package installation | high | mitigate | Preserve blocking Better Auth provenance/tarball checkpoint before package installation. |

Residual threats: Phase 3's eventual byte provider or deployment storage policy could violate this contract if it serves a path before owner authorization. Phase 3 must retain the two-account direct-request tests and add storage-provider tests before real score bytes are introduced.
